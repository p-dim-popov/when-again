# Epic 2: i18n (Bulgarian + English) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A leaf `i18n` module (engine, `t()`, detection, switching) with per-module push-registered strings, wired into the boot sequence, and the existing home screen migrated onto it with a temporary on-device language toggle.

**Architecture:** `i18n` is a pure leaf module — it imports no other feature module. Feature modules ship their own `strings.ts` and the composition root (`src/app/main.tsx`) push-registers them via `registerStrings`, keeping the dependency graph acyclic. Language is resolved once at boot (`settings.language ?? detectLanguage()`); switching persists to settings and calls `location.reload()`, so there is no reactive context. Type safety comes from a `TranslationKeys` interface declared in `i18n/index.ts` that each module augments — the same augmentation pattern `src/app/router.tsx` already uses for TanStack's `Register`.

**Tech Stack:** TypeScript, React 19, `Intl` (PluralRules / NumberFormat) — no new dependencies. Vitest + `fake-indexeddb` for units; Playwright for e2e.

## Global Constraints

- **No new dependencies.** Plurals and formatting use the platform `Intl` APIs; persistence reuses the existing `settings`/`db` modules. TypeScript stays `~6.0.3`.
- **No server, no analytics, no network calls.** Localization is fully local and works offline.
- **Modulith rules:** cross-module imports only via `modules/<name>/index.ts`; no cycles; nothing imports `src/app/`. `i18n` is a **leaf** — it imports no feature module. New dependency edges this epic: `home → i18n`, `home → settings`, and the composition root `src/app → i18n, settings, home`.
- **`Language` type:** `i18n` exports its own `Language = 'bg' | 'en'`. The existing `settings.Language` is structurally identical (`'bg' | 'en'`), so `settings.language` (`Language | null`) interoperates by assignment — no import edge from `i18n` to `settings`. Do **not** modify the merged `settings` module.
- **`TranslationKeys` is declared in `i18n/index.ts`** (not an internal file), so modules augment it through the public API path (`declare module '../i18n'`). Augmentations against different relative specifiers that resolve to the same `index.ts` merge globally.
- **Switch = reload.** Persist `updateSettings({ language })` then `location.reload()`. "Auto" persists `language: null`.
- **Detection fallback: `en`.**
- **TDD** for every unit: write the failing test, watch it fail, implement, watch it pass.
- **Keep green before every commit:** `npm run lint`, `npm run format:check` (run `npm run format` when needed), `npm run typecheck`, `npm test -- --run`.
- **Branch:** work continues on `epic-2-i18n` (already created; holds the design-spec commit). Do NOT push to `main` directly.
- **Commit messages:** plain conventional style, no Claude session links.
- **BG copy:** the Bulgarian strings in this plan are drafts. The repo owner is a Bulgarian speaker — confirm wording during review; the mechanism does not depend on exact copy.

`src/modules/i18n/i18n.ts`:

```ts
import type { TranslationKeys } from './index';
import type { Language, StringValue, Strings, TParams } from './types';

const registry: Record<Language, Strings> = { bg: {}, en: {} };
let active: Language = 'en';

export function registerStrings(lang: Language, strings: Strings): void {
  registry[lang] = { ...registry[lang], ...strings };
}

export function initI18n(language: Language): void {
  active = language;
}

export function getActiveLanguage(): Language {
  return active;
}

function interpolate(template: string, params?: TParams): string {
  if (!params) return template;
  return template.replace(/\{(\w+)\}/g, (match, key: string) =>
    key in params ? String(params[key]) : match,
  );
}

export function t(
  key: keyof TranslationKeys & string,
  params?: TParams,
): string {
  const value: StringValue | undefined = registry[active][key];
  if (value === undefined) return key;
  if (typeof value === 'string') return interpolate(value, params);
  const count = Number(params?.count ?? 0);
  const category = new Intl.PluralRules(active).select(count);
  const form = value[category] ?? value.other;
  return form === undefined ? key : interpolate(form, params);
}
```

```ts
import type { Language } from './types';

interface NavigatorLanguages {
  languages?: readonly string[];
  language?: string;
}

export function detectLanguage(nav: NavigatorLanguages = navigator): Language {
  const languages = nav.languages ?? (nav.language ? [nav.language] : []);
  for (const entry of languages) {
    const primary = entry.toLowerCase().split('-')[0];
    if (primary === 'bg') return 'bg';
    if (primary === 'en') return 'en';
  }
  return 'en';
}
```

export interface SwitchDeps {

// TEMPORARY: powers the home-screen language toggle until the Settings UI epic

## Notes for the implementer

- **Global i18n state is intentional.** `registry` and `active` are module-level singletons resolved once at boot; reload-on-switch is what makes this safe (no mid-session language change to invalidate rendered output).
- **Augmentation visibility:** the `tsconfig` `include: ["src"]` compiles every `strings.ts`, so `TranslationKeys` augmentations are globally visible — `HomeScreen.tsx` typechecks `t('home.title')` without importing `strings.ts`. This mirrors the existing `Register` augmentation in `src/app/router.tsx`.
- **Do not add DOM test tooling** (jsdom / testing-library) for this epic — component behavior is covered by typecheck, build, and Playwright.
- **Deferred (tracked elsewhere):** the permanent Settings language control (Settings UI epic); the React store decision (issue #4).
